# Digital Wellness AI - dependencies
# Core data / ML
#
# scikit-learn is PINNED, not floored (`==`, not `>=`), because the
# artifacts under artifacts/*.pkl are joblib/pickle dumps of fitted
# sklearn Pipelines/estimators (see artifacts/model_info.json ->
# "sklearn_version"). Pickle compatibility across sklearn *minor*
# versions is not guaranteed - unpickling health_classifier.pkl /
# health_regressor.pkl / persona_model.pkl under any other minor
# version can raise ModuleNotFoundError (internal module paths such
# as `_loss` moved between 1.8 and 1.9) or silently deserialize into
# a subtly different estimator. If you retrain and re-save the
# artifacts under a newer sklearn, bump this pin AND
# artifacts/model_info*.json in the same change.
pandas>=2.0
numpy>=1.24,<2.5
scikit-learn==1.8.0
joblib>=1.3
xgboost>=1.7        # optional: model_factory.py degrades gracefully if absent

# Explainability
#
# numpy is capped at <2.5 above specifically because this package's
# numba dependency (used by shap/utils/_clustering.py) hard-requires
# numpy<=2.4 - `import shap` raises ImportError on numpy 2.5+
# ("Numba needs NumPy 2.4 or less"). This was previously masked
# everywhere in this codebase's own test suite by
# tests/_test_support.py's offline shap stub (installed into
# sys.modules before any test imports services.shap_service), so it
# went unnoticed until building api/main.py and booting the FastAPI
# backend with a real `uvicorn` process outside that test-only
# stub-injection path, which surfaced it immediately. The Streamlit
# app was equally exposed to this the whole time; it just never got
# run standalone (outside pytest) in an environment where numpy had
# drifted to 2.5+. Confirmed via full-suite re-run after this pin
# (357/357 passing) that pinning numpy down doesn't affect anything
# else - and doing so also fixes every test in the suite to exercise
# the REAL shap.TreeExplainer instead of the offline ablation stub
# (test-suite wall-clock time dropped by more than half as a result).
shap>=0.44

# FastAPI backend (api/) - a thin HTTP interface over the same
# services/ layer the Streamlit app uses; see api/main.py.
#
# fastapi/starlette are pinned to a range, not left fully open, for the
# same reason as the scikit-learn pin above: an unconstrained install

# additionally constrained to stay compatible with streamlit's own
